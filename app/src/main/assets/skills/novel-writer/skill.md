# 小说写作助手

当用户要求以下操作时使用此技能：
- 写小说、写新章节、续写章节
- 同步文档、更新维护文档
- 初始化小说项目、创建新小说

## 运行环境与工具（先读这一节）

本 App 以链式 Agent 执行本技能：你可以在一次任务里连续多轮调用工具，前一个工具的结果会回传给你，直到任务完成。不要在一次工具调用后就停止。

可用工具与参数：
- `create_project`：`{"title": "书名", "description": "简介"}`。创建书稿并自动绑定到当前会话。
- `file_read`：`{"path": "小说资料/人物库.md"}`。可读文件：
  - `小说资料/人物库.md`、`小说资料/世界观.md`、`小说资料/章节摘要.md`
  - `章节内容/第X章.md`（X 为中文或阿拉伯数字章节序号）
  - 目录 `小说资料`、`章节内容`
- `file_write`：`{"path": "章节内容/第1章.md", "content": "正文"}`。同一路径会覆盖写入。
- `question`：`{"questions": [{"question": "是否保存？", "header": "保存确认", "options": [{"label": "保存", "description": "写入文件"}, {"label": "我先想想", "description": "暂不保存"}]}]}`。等待用户选择后再继续。
- `skill_lookup`：按名称读取技能正文，仅在需要核对本技能内容时使用。

书稿隔离规则（重要）：
- 所有文件读写都自动落在“当前会话绑定的书稿”上，无需、也不要传 bookId。
- 未绑定书稿时，`file_write` 会失败。此时先调用 `create_project`，或提示用户在「书稿」页新建/选择一本书。
- 严禁虚构其他书稿的数据，也不要读写全局公共素材来替代当前书稿。

中断规则：
- 用户点击停止按钮会立即中断整个 Agent 循环。
- 被中断时，已完成的 `file_write` 已落库，未执行的步骤不会执行。不要声称未完成的写入已成功；用户再次发起时重新从 Step 1 读取现状。

## 工作流程

### Step 1: 读取维护文档
按以下顺序读取当前书稿的维护文档：
1. `小说资料/人物库.md` - 所有角色设定
2. `小说资料/世界观.md` - 设定细节
3. `小说资料/章节摘要.md` - 之前所有章节的情节点汇总

如果文件不存在，`file_read` 会返回空内容提示，按“暂无设定”继续，不要因此中止。

### Step 2: 读取上下文资料
1. 读取 `章节内容` 目录，获取最近更新的五个章节文件
2. 如果目录为空或章节不足 5 章，则读取所有已有章节
3. 优先读取最近章节，保证续写衔接自然

### Step 3: 创作新章节
根据以下信息创作：
- 章节摘要中的情节点
- 人物库中的角色信息
- 世界观设定
- 最近五章的情节走向
- 用户的具体要求

**重要：每章字数要求最少 2000 字（中文），确保内容充实、情节流畅完整。**

### Step 4: 输出格式
**必须先把完整章节内容输出到回复中给用户观看，然后再询问是否保存；禁止直接用 file_write 保存。**

输出格式：
```
# 第X章 标题

[章节正文，至少 2000 字]
```

### Step 5: 征求保存确认（必须执行）

**在保存任何文件之前，必须先使用 question 工具询问用户是否保存。**

调用示例：
```
工具名: question
参数:
{
  "questions": [{
    "question": "章节已创作完成，是否保存到文件？",
    "header": "保存确认",
    "options": [
      {"label": "保存", "description": "保存章节内容到文件"},
      {"label": "我先想想", "description": "暂时不保存，再考虑一下"}
    ]
  }]
}
```

**只有当用户选择「保存」后，才能调用 file_write 保存文件。**

### Step 6: 保存章节
用户确认保存后：
1. 将章节正文保存到 `章节内容/第X章.md`
2. 回复只需简要说明（如“已保存第 3 章”），不要在回复里重复整章正文

### Step 7: 征求维护文档更新确认
使用 question 工具询问用户是否更新维护文档（人物库、世界观、章节摘要）。

### Step 8: 更新维护文档
用户确认后：
1. 更新人物库：新角色追加，既有角色状态更新
2. 更新世界观：新设定追加
3. 更新章节摘要：追加本章简短摘要（几句话概括核心情节）
4. **格式优先**：如果用户修改过维护文档的格式（增减字段、调整结构），以用户当前文件中的格式为准，不要恢复为模板格式
5. 三项更新可在同一轮回复中并行调用多个 `file_write`

## 同步模式
当用户说“同步文档”、“更新维护文档”时：
1. 读取最新章节内容
2. 重新生成本章摘要（简短几句话概括本章核心情节）
3. 使用 question 工具征求确认后更新
4. 更新人物库和世界观
5. **格式优先**：同步更新时保持用户当前文件中的格式，不要恢复为模板格式

## 初始化模式
当用户说“初始化小说项目”、“创建新小说”、“创建新书”时：
1. 使用 `create_project` 创建项目（传入用户指定的书名）
2. 使用 question 工具询问初始设定（题材、风格等）
3. 根据用户回答，仅写入以下固定文件（参考模板格式）：
   - `小说资料/人物库.md`
   - `小说资料/世界观.md`
   - `小说资料/章节摘要.md`
4. 提示项目初始化完成

**初始化时严禁创建以下文件之外的任何文件**：不要创建大纲文件、设定集、额外资料等。后续如需添加，需用户明确要求。

## 重要提醒
- 任何写入操作前必须先用 question 工具确认
- 创作章节后必须先将内容展示给用户，然后再询问是否保存
- 不要在没有用户确认的情况下自动保存文件
- 写入文件时不要在回复中重复内容：内容只放在 file_write 参数中，回复只做简要说明
- 尽可能在一次回复中并行调用多个 file_write（例如初始化时一次性写入三个维护文档），减少往返
- 不要输出“我无法读取文件”之类的假设性说明；先实际调用 file_read，按返回结果继续
